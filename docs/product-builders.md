# Shared product creation pipeline

Implemented entry: `/build/new`. Product workspace: `/build/{id}`. The canonical public Sales page is `/product/{slug}`; `/b/{slug}` remains the compatible delivery/checkout route.

New UI creation entries choose a format and starting source, then open the relevant work. Mini course and Full/video course go directly to Curriculum with Upload recording, Write a lesson and Add a resource choices. Save one useful lesson privately before expanding settings. Existing-content entry selects recording upload; manual entry selects writing. Typed teaching is kept when switching methods, and recording attachment retains the existing lesson. Complete the product name, audience and Outcome in Product details as the course develops. Book/eBook, Guide, Playbook, Template kit, Challenge, Consulting/Mentorship, Coaching session, Community and Custom keep their relevant fields, section labels and readiness rules. AI, original uploads and manual authoring share the same persistent product identity.

## Creator clarity release

Overview is the product’s next-action dashboard. Launch review (`/build/{id}?area=review`) is a separate destination for required-content checks, exact saved-version editorial approval, the private delivery preview and explicit delivery publication. Price & access (`area=commerce`) holds money, access and availability settings and offers direct repair actions for unmet requirements. Product content can be published without opening checkout. The Sales page remains a separate public publication.

Zero in an unfinished paid offer is not a free offer. The shared offer projection displays Price not set for an unset or unusable paid amount, consistently in draft and public sales-page rendering. Free / lead magnet or a free membership tier must be chosen explicitly. Payment and access authorization still run through the existing server checks; a label never enables a purchase.

The common marketing brief inherits blank audience, Outcome, tone and inclusions from saved product facts. A nonblank shared answer is an override. Product description is not substituted for Outcome, and showing inherited defaults does not make an untouched editor dirty. Updating a shared answer does not rewrite existing VSL, campaign, page or approved email copy. See [the release checklist](creator-clarity-release-checklist.md) for combined checks and provider boundaries.

The contextual assistant appears on the right, minimizes without clearing history or unsent answers, and starts minimized on small screens. Suggestions require review and explicit application. The existing administrator-managed AI connection, shared planning allowance, full-product quota, credit reservations/refunds and verified owner exception are reused. Original files and private meeting/community URLs are excluded from AI context. No provider credential is requested from a customer.

Both text providers receive the response JSON schema explicitly. The assistant accepts `null` for unused optional edits and question lists, then validates the normalized result against its strict content limits before saving it. Empty edit proposals become discussion-only replies; malformed or oversized edits are rejected without modifying the product, and reserved customer credits are refunded. Validation diagnostics contain only provider and schema error paths/codes. `npm run test:ai-format` covers both provider transports and the actual planning ledger; `npm run test:ai-format:runtime` exercises the built HTTP routes with isolated provider responses.

Product details is the assistant’s default task. Essentials, type-specific fields, and individual field actions provide explicit scopes; Outline and Refine excerpt remain separate choices. Book details include Subtitle, Book premise, and Reader experience level. Details requests exclude manuscript content and old outline interviews from the model context, have a response schema without sections, suppress unrelated follow-up questions, and reject/refund wholly out-of-scope responses. Applicable field edits merge into existing draft fields only after review; existing sections, recordings, files, private delivery URLs, and sales settings are preserved. An explicit outline has separate append/replace confirmation and cannot silently truncate the existing manuscript to fit a limit. Previously applied content is not automatically removed.

Full generation uses the existing staged generator. Generation results are captured independently before later manual saves; applying a result saves current metadata first and preserves original uploads. Version checks protect concurrent edits. Failed saves remain recoverable without endlessly retrying an unchanged invalid draft. A completed result is marked applied; another full generation requires a deliberate new run under current allowance/credit rules.

## Publication and selling

Publication checks product-specific content and deep asset integrity, but does not require a price or payment connection. A page without enabled sales shows that purchases are unavailable. Public metadata contains no manuscript/lesson bodies, original resource IDs, recordings, service meeting links or private community invitations. Optional covers use a published-image-only endpoint.

Start selling is a separate server operation. It requires the latest published version, a valid price, explicit platform payment enablement, a correctly configured connected-account webhook, and a freshly verified eligible Stripe account. Services require session scope, preparation, a private meeting URL and upcoming availability. Community access uses an external HTTPS invitation and member resources; this release does not create an in-app discussion platform. Challenges are self-paced, not scheduled cohorts or email drip delivery. AI produces written material/scripts; creators upload their own recorded classes. Written content exports as printable HTML, not a claimed native PDF.

Checkout freezes the reviewed delivery version before payment. Paid customers receive their purchased content through the authenticated/cookie-protected portal. Future published PDF updates are additive for customers already paid at publication; original PDFs remain available. Pending checkout A → publication B → payment A preserves A. New course content and unrelated resource types are not automatically granted. Refund/dispute revocation applies to original content and update grants.

Legacy sold products and file-sale revisions retain their existing editors and entitlement behavior. Adoption refuses direct purchases, bundle/upsell inclusion and commerce purchases. Historical checkout/quote/free-download endpoints cannot expose new builder content. Existing marketing tools remain reachable from the builder without duplicating content or payment editing.
